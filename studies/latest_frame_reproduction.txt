Updater definition:
  Preserve the original model action and observation. Immediately before
  commitment use the newest admitted image and the same native grayscale NCC
  vision kernels: radius 12, min score .8, ambiguity margin .05, plateau max 4.
  Retain the original RGB target patch as ordinary pending-action identity.
  Reject a candidate with RGB mean absolute difference >2/255. A completely
  unchanged frame preserves the original action, including model errors.
  Missing, ambiguous or changed-appearance targets yield a scored no-action
  result, with a recorded reason. No extra model call, restart, operation switch,
  event ledger, dependency matrix, or selective meta-control is added.
  The existing fixed-font decoder supports type arguments; it is not exercised
  in this three-task run. Its font/color prior is explicit, not generic OCR.
  Python orchestration, pixel staging, template extraction and the RGB check
  use the CPU. CUDA allocations are prepared before episode start. All per-
  action copies, kernels and checks are included in measured updater runtime.
  An AgentState allocation is zeroed scratch required by the existing vision
  kernel ABI, used for Proposal fields only; no event-history control is linked.

Measurement and interpretation:
  Native is legacy C++ + detector, NOT full Chronotope. Its prompt and grounding
  differ from Agent S3, and its color detector receives benchmark target color.
  The added baseline receives only model output and observation pixels. Only
  Agent S3 Keep vs Agent S3 latest-frame is a matched-policy updater comparison.
  Success is recomputed by the unchanged evaluator at benchmark action receipt.
  Notification setting = lifetime. Button/Trading setting = state-change delay;
  their independent overall task deadline is 32 seconds.
  All arms use the same wall-clock advancing environment, 16.666667 ms frame
  cadence, 30 ms publication delay and 20 ms simulated action-delivery route.
  Frame publication is lazily caught up after blocking computation. This is
  not physical asynchronous application capture. The newest frame is sampled
  once at updater entry; updater runtime is charged, with no repeated update.
  Scheduled receipt timestamps are distinguished from measured submit/receipt
  handler timestamps. There are no physical application ACK timestamps.
  E-to-A p50/p95 are conditional on receipt; no-action latency is missing,
  never zero. Receipt counts and abstentions accompany the latency summaries.
  Model-call/token totals include planner, grounding, reflection and retries.
  HTTP/setup/contract errors are unscored infrastructure records, with logs;
  remaining independent planned cases continue. No case is automatically retried.
  Each completed scored case, including competence failures, stays in its cell.
  Success uncertainty: Wilson 95% intervals. Paired differences use equal seeds
  AND verified equal first input/image hashes, with deterministic paired
  bootstrap intervals (2,000 resamples). Small partial samples are inconclusive.
  A global NCC search may reject an otherwise valid wide/untextured button as
  ambiguous. Such abstentions are a limitation of this conservative baseline;
  they are not evidence that an event-history representation is necessary.
  Expiration/reversal operation-change flags are derived post hoc by the
  evaluator. No application state or future ground truth reaches the updater.
